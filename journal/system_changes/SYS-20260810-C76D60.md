# System Change: Add Yahoo Finance MCP as first read-only financial data adapter

- Date/time: 2026-08-10T11:51:03-03:00
- Change ID: SYS-20260810-C76D60
- Change class: A
- Status: PROPOSED_AUTONOMOUSLY_ALLOWED

## Problem observed

The Capital Agent had no structured market-data source, only WebSearch/WebFetch for qualitative research. Human owner asked about useful integrations for analysis/decisions; researched real MCP options and selected a free, no-credential, read-only one to start.

## Evidence

`npm view yahoo-finance-mcp-server` confirmed the package is real: v1.2.5,
MIT license, published 3 days before this change by a maintainer whose npm
account matches the GitHub repository owner, no npm-level dependencies
(it shells out to a local Python/`yfinance` runtime rather than bundling a
JS reimplementation — this machine already has Python 3.12, but `yfinance`
itself has not been separately verified as installed; first real
invocation from a Claude Code session will surface this if missing).
`WebFetch` against the GitHub README (quoted in the approval package,
`approvals/pending/APR-20260810-7BFB0C.md`) described the tool surface and
explicitly read-only nature. Full source code was not line-by-line audited;
this limitation is stated in the approval's critic assessment, not hidden.

## Proposed change

Added .mcp.json configuring the yahoo-finance-mcp-server npm package (npx -y yahoo-finance-mcp-server) as an MCP server, exposing quotes, historical prices, fundamentals, analyst ratings and news via yfinance/Yahoo Finance public endpoints. Went through the full critical-decision approval process first (APR-20260810-7BFB0C, new_readonly_financial_adapter_is_always_critical trigger), including critic assessment, alternatives considered, and policy checks, per HUMAN_GATES.md Gate H4 and CRITICAL_DECISIONS.md. Confirmed the npm package exists, is MIT-licensed, and matches the reviewed GitHub README. Also fixed a prose-vs-machine-readable gap found while preparing this approval: CRITICAL_DECISIONS.md already stated 'enabling a new read-only financial data adapter' is always critical, but config/critical_decisions.json had no matching field and classify_critical() had no matching parameter -- added new_readonly_financial_adapter_is_always_critical to the config and a new_readonly_financial_adapter parameter/CLI flag to classify-decision and request-approval.

## Expected benefit

Gives the Capital Agent structured, free, read-only market data for the upcoming first opportunity research cycle, without any credential to manage or write capability to guard against. Closes a real governance gap (the missing machine-readable mirror of an existing prose rule) discovered by actually exercising the approval process end to end for the first time, rather than leaving it untested.

## New risks introduced

See the approval package's "Critic assessment" for the full analysis
(unaudited third-party code, individual maintainer, possible bad/stale
data). Additionally: `yfinance` may not be installed in this machine's
Python environment yet, which would surface as a runtime error on first use
rather than at configuration time — not a security risk, an operability one.

## Authority impact

None. Read-only data source; no credential created; no path to
`data/ledger.csv` or `execution/`. Governance-side, this *reduces* a gap
(prose/config mismatch on when a data adapter is critical), it does not
expand authority anywhere.

## Rollback plan

Delete `.mcp.json` (or remove the `yahoo-finance` entry) and restart any
Claude Code session; the server stops being available. No data to migrate
back, since it was never given write access to anything.
