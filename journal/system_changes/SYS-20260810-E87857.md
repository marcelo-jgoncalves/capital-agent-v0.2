# System Change: Track reserve instruments (e.g. Tesouro Selic) so equity floor stops understating patrimony

- Date/time: 2026-08-10T12:07:48-03:00
- Change ID: SYS-20260810-E87857
- Change class: A
- Status: PROPOSED_AUTONOMOUSLY_ALLOWED

## Problem observed

While preparing the first real Human Execution Request (parking idle reserve in Tesouro Selic per DEC-20260810-A032A0), found that recording a BUY via confirm-execution reduces cash_balance() as intended, but current_equity_floor() (Phase 0: cash-only) had no way to add back the value of the resulting position. Moving a large share of idle cash into Tesouro Selic would have made the tracked equity floor crash toward zero, incorrectly blocking future legitimate proposals under policy checks that depend on it.

## Evidence

Discovered by walking through the actual intended flow before executing
anything real: `confirm-execution`'s ledger effect (verified by
`tests/test_custody_and_execution.py`) subtracts a BUY's total from
`cash_balance()`; `current_equity_floor()` was, by design (Phase 0 comment),
`cash_balance()` only. Traced the consequence: booking BRL 500+ of a
BRL 1,000 equity into Tesouro Selic this way would have dropped the tracked
floor to under BRL 500, which `max_single_live_allocation_brl`/
`minimum_cash_reserve_brl` (both computed from the floor) would then
compute from a wrong, understated base -- silently over-restricting every
subsequent proposal, including the already-planned BRL 20 experiment
(`EXP-20260810-1F7147`).

## Proposed change

Added data/reserve_assets.json, load_reserve_assets()/reserve_assets_value(), and a new record-reserve-asset CLI command. Book value is never a free-form number -- it is derived from the referenced completed Human Execution Request's confirmed executed_total_brl, so it always traces back to a real, human-confirmed transaction. current_equity_floor() now returns cash_balance() + reserve_assets_value(). cmd_status and build_current_state updated to surface booked reserve assets explicitly.

## Expected benefit

Lets the system correctly park reserve capital in low-risk near-cash instruments without corrupting its own equity tracking. Keeps the 'never overstate equity' invariant: an unbooked position still understates equity (safe direction), but a booked one is now accurate rather than needlessly conservative to the point of being wrong.

## New risks introduced

- `book_value_brl` is valued at cost (the confirmed execution total), never
  marked to market or accrued forward. For a floating-rate instrument like
  Tesouro Selic this understates true value over time (safe direction) but
  means the equity floor will drift slightly conservative the longer an
  asset is held without a redemption/re-booking event. Acceptable for Phase
  0; a future price-feed-backed marking mechanism (e.g. via a BCB/Tesouro
  Direto adapter) would improve precision, not correctness.
- `record-reserve-asset` trusts that a `BUY`-type completed execution really
  represents a low-risk, near-cash instrument (nothing stops booking a
  volatile stock purchase as a "reserve asset" via this same command). Not
  enforced in code because the risk classification is a judgment call this
  command cannot verify; mitigated by requiring `--category` to be stated
  explicitly (default `reserve`) and by this being an AI/human-operated CLI
  action subject to the same auditability as everything else, not a
  silent/automatic step.

## Authority impact

None. This is an accounting-precision fix; it does not change any hard
policy value, and if anything makes policy checks (which depend on the
equity floor) more accurate rather than more permissive by default (an
unbooked position still understates, which is the conservative direction).

## Rollback plan

Delete `data/reserve_assets.json` (or empty it to `[]`) and revert this
commit; `current_equity_floor()` returns to cash-only behavior. No data is
destroyed by rollback -- the underlying ledger and execution records are
untouched either way.

## Validation plan

`python -m unittest discover -s tests`; manually confirm via `status` that
`verified_equity_floor_brl` matches `verified_cash_brl + reserve_assets_brl`.

## Tests/checks performed

Added `ReserveAssetTests` (5 tests): equity floor understates before
booking, booking restores it, unconfirmed/non-BUY execution IDs are
refused, and book value is proven to come from the execution record rather
than a free-form argument. Full suite: 48/48 passing
(`python -m unittest discover -s tests`, run 2026-08-10).
