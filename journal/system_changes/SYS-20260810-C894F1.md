# System Change: Register CapitalAgentScheduler in Windows Task Scheduler

- Date/time: 2026-08-10T11:36:28-03:00
- Change ID: SYS-20260810-C894F1
- Change class: A
- Status: PROPOSED_AUTONOMOUSLY_ALLOWED

## Problem observed

src/scheduler.py existed but had never been invoked on a real external cadence, so the system still depended on a human manually running it. ROADMAP.md Phase 1 names this as a required step, and the human owner asked for a useful integration to install.

## Evidence

Human owner explicitly asked "alguma integração que podemos instalar e que
pode ser útil?" in this session; the scheduler cadence was recommended as the
highest-priority option (directly closes a named `ROADMAP.md` Phase 1 gap,
zero financial risk) and the human owner confirmed via
`AskUserQuestion` to proceed with it over the alternatives offered (GitHub
remote, doing nothing now).

## Proposed change

Added scripts/run_scheduler.ps1 (wrapper: cd into repo, run python src/scheduler.py run, append output to state/scheduler_run.log with correct UTF-8 encoding). Registered a Windows Task Scheduler task named CapitalAgentScheduler via Register-ScheduledTask, running the wrapper every 15 minutes indefinitely. Documented management commands (status/disable/unregister) and the fact that it only ever calls scheduler.py run (no AI call, no ledger write, no financial capability) in scheduler/README.md. Updated ROADMAP.md Phase 1 to mark this item done.

## Expected benefit

Closes a concrete Phase 1 gap: the system can now enqueue scheduled/triggered job tickets without a human remembering to run it. Verified end to end: manually started the task via Start-ScheduledTask, confirmed LastTaskResult=0 and a correctly formatted log entry, confirmed NextRunTime is set 15 minutes out.

## New risks introduced

- Hardcoded machine-specific paths in `scripts/run_scheduler.ps1` (python
  interpreter path, repo path). If the repository moves or Python is
  reinstalled elsewhere, the task will fail silently until someone checks
  `state/scheduler_run.log` or `Get-ScheduledTaskInfo`. Documented in
  `scheduler/README.md` with the re-registration command.
- The task now runs every 15 minutes indefinitely on this machine. It has no
  capability to affect real money (verified: `src/scheduler.py` contains no
  `append_ledger` call, no network call, no AI call — it only reads
  config/state and writes `state/pending_jobs.json`/`state/scheduler_state.json`),
  so the operational risk is limited to disk/log growth and job-queue buildup
  if tickets are never dequeued, not financial risk.
- `state/scheduler_run.log` grows unbounded over time (never rotated). Low
  priority given how small each entry is; noted as a future Class A cleanup
  if it becomes a nuisance.

## Authority impact

None. This automates *when* the scheduler's deterministic checks run; it
does not change what those checks can do, add any credential, or touch
`config/policy.json`.

## Rollback plan

`Unregister-ScheduledTask -TaskName "CapitalAgentScheduler" -Confirm:$false`
removes the task immediately (documented in `scheduler/README.md`); deleting
`scripts/run_scheduler.ps1` and reverting this commit removes the rest. No
data loss risk — `state/*.json` remain valid even if the task is removed.

## Validation plan

Manual: `Start-ScheduledTask`, then check `Get-ScheduledTaskInfo` for
`LastTaskResult -eq 0` and a populated `state/scheduler_run.log` entry with
correct (non-garbled) encoding.

## Tests/checks performed

- Ran `scripts/run_scheduler.ps1` manually once before registering the task:
  confirmed it queued 18 jobs correctly on the real (first-ever) scheduler
  run for this repository — a genuine activation, not test data, so left in
  place rather than reverted.
- Found the first version of the wrapper produced a mixed-encoding
  (UTF-8/UTF-16) log file due to PowerShell's native-command redirection
  (`*>>`) defaulting to UTF-16; fixed by capturing output via `Out-String`
  and writing with `Add-Content -Encoding utf8`. Reran and confirmed the log
  is now plain readable UTF-8.
- Registered the scheduled task, ran it via `Start-ScheduledTask`, confirmed
  `LastTaskResult = 0` and `NextRunTime` set ~15 minutes out.
- `python -m unittest discover -s tests`: 42/42 passing (unaffected by this
  change; no `src/` logic changed, only a new wrapper script and OS-level
  registration).
