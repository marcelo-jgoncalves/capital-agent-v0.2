# System Change: Platform-integration restructuring (EXP-001 preparation)

- Date/time: 2026-08-13T16:30:00-03:00
- Change ID: SYS-20260813-4149BC
- Change class: B (governance-strengthening documentation + additive, non-financial code/schema; no increase in financial authority or risk capacity)
- Status: implemented, validated

## Problem observed

The repository's governance, custody, criticality, evaluation, context and
scheduler architecture was already largely correct and complete (verified in
discovery — see below), but it had no formal treatment of the specific,
concrete integration this project has always been heading toward: onboarding
the owner's pre-existing business platform (site + blog) as the Capital
Agent's first planned operational experiment. Missing pieces: an EXP-001
record, an explicit domain/sunk-cost accounting exclusion rule, an activation
gate checklist, and a documented platform-as-asset boundary (platform keeps
its own identity; Capital Agent never becomes "the platform's identity").
Without these, a future AI operator asked to "onboard the platform" would
have no canonical place to record the plan without either inventing ad hoc
rules or risking silent activation / accidental cost attribution.

- Discovery read of README.md, START_HERE.md, AI_OPERATING_MANUAL.md,
  ARCHITECTURE.md, CLAUDE.md, AGENTS.md, CONTEXT_MANAGEMENT.md,
  CRITICAL_DECISIONS.md, EVALUATION_CRITIC_SYSTEM.md, HUMAN_GATES.md,
  INVESTMENT_POLICY.md, ROADMAP.md, SYSTEM_EVOLUTION.md, config/*, src/*,
  tests/*, experiments/*, execution/*, approvals/*, journal/*, context/*.
- `grep` audit for obsolete/contradictory terms (live execution, autonomous
  execution, broker/exchange adapter, write credentials, financial write,
  Tier 3, automatic order, withdrawal, bounded autonomous financial
  execution) found no active occurrences outside prohibitions and one prior
  historical record (`journal/system_changes/SYS-20260810-BD6581.md`)
  documenting an earlier, already-completed removal of exactly this class of
  concept. No new contradictions were introduced or found.
- No `EXP-001` (or platform) record existed anywhere before this change;
  `experiments/active/` contained only one unrelated, already-killed
  experiment (`EXP-20260810-1F7147`).
- `INVESTMENT_POLICY.md` listed "domains and infrastructure" as an eligible
  capital use (section 2) but had no rule excluding an owner-provided domain
  from Capital Agent accounting — a genuine gap relative to this
  restructuring's mandate.

## Proposed change

1. Add `INVESTMENT_POLICY.md` section 14: domain and pre-existing platform
   costs are `EXTERNAL / OWNER-PROVIDED ASSET`, `attributable_to_capital_agent:
   false`, with an explicit six-condition incremental-cost test for any
   post-activation platform-related cost.
2. Add `ARCHITECTURE.md` section 6a: platform-based experiments are an asset
   under management, not the Capital Agent's identity; publication remains
   critical by default per `CRITICAL_DECISIONS.md`.
3. Create `experiments/active/EXP-20260813-62C22E.json` (`code: "EXP-001"`)
   with `state: PLANNED`, `status: planned`, `activation.activated: false`,
   `activation.activation_date: null`, zero budget/capital deployed, null
   (not fabricated) metrics, and explicit cost-attribution fields mirroring
   section 14.
4. Create `experiments/EXP-001-ACTIVATION-CHECKLIST.md` — platform,
   commercial and Capital-Agent readiness checklist; explicit that checklist
   completion never itself activates the experiment, only an explicit human
   activation record does.
5. Add `tests/test_platform_exp001.py` (12 tests) covering: EXP-001
   planned/not-activated state, zero capital deployed, domain/sunk-cost
   exclusion, no fabricated metrics, checklist existence and language, policy
   documentation, and absence of forbidden legacy terms in the new content.

## Expected benefit

A future AI operator (this one or another provider) asked to progress the
platform integration has a canonical, machine-readable starting point that
cannot be mistaken for an active experiment, and cannot accidentally count
the domain or historical platform work as Capital Agent cost.

## New risks introduced

None material. This change is additive documentation/schema plus a
zero-budget experiment record; it introduces no financial write path, no
change to any hard limit, and no reduction of any existing control. The
`experiments/EXP-001-ACTIVATION-CHECKLIST.md` "Capital Agent readiness"
section pre-checks items that were already true before this change
(ledger, scheduler, critic, etc. already existed) — those checkmarks reflect
prior state, not new work from this change, and are documented as such.

## Authority impact

None. No financial authority, credential, or risk limit changed. EXP-001
remains PLANNED/NOT ACTIVATED; the experiment performance clock has not
started; no capital has moved.
