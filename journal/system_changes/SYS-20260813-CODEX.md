# System Change: Codex CLI integrated as second reasoning provider

- Date/time: 2026-08-13T17:10:00-03:00
- Change ID: SYS-20260813-CODEX
- Change class: B (adds a new provider adapter and reasoning-router
  abstraction; does not touch financial authority, custody, or human-gate
  logic — those documents are unmodified)
- Status: PROPOSED_AUTONOMOUSLY_ALLOWED

## Problem observed

The Capital Agent had only one practically usable reasoning provider
(Claude, run interactively via `adapters/ai_providers/manual_adapter.py`).
`prompt-integracao-codex-capital-agent.md` requested formally incorporating
the already-installed, already-authenticated Codex CLI as a second
reasoning/engineering provider, to gain cognitive diversity, reduce
anchoring/confirmation bias, add independent critique for material
decisions, and support editorial research (topic discovery for the future
business-platform experiment, EXP-001, which remains not started).

## Hypothesis

A provider-neutral task abstraction plus a dedicated, least-privilege Codex
adapter lets the system route reasoning tasks to whichever provider is
available and appropriate, without making either provider mandatory or a
policy authority, and without introducing any new financial-write surface.

## Benefits

- Independent second opinion for critical decisions
  (`src/critic.py`), never resolved by majority vote.
- Blind independent topic discovery structure for editorial research
  (`src/editorial_research.py`), reducing anchoring risk once EXP-001
  content work begins.
- Engineering review capability (code review, adversarial tests, policy
  audit) via `src/engineering_review.py`.
- Auditable AI run history (`state/ai_runs/`) with secret scrubbing.
- Provider performance signal collection
  (`src/provider_registry.py`, `evaluation/provider_performance.py`)
  without inventing composite scores or causality.
- System keeps functioning identically if Codex is absent/unavailable —
  verified by `PROVIDER_UNAVAILABLE`/`CRITIC_UNAVAILABLE` fallback tests.

## Risks

- New subprocess surface (`codex_cli.run_codex_exec`): mitigated by
  list-form `subprocess.run` (no shell), sandbox allow-list
  (`read-only`/`workspace-write` only, `danger-full-access` unreachable),
  and `TaskEnvelope.validate()` rejecting any financial-write-shaped
  capability before Codex is ever invoked.
- External/web content Codex might bring back is
  `UNTRUSTED_EXTERNAL_CONTEXT` by convention in the docs
  (`EDITORIAL_RESEARCH_SYSTEM.md`) — not yet enforced in code because web
  search is not confirmed reachable via `codex exec` on the installed CLI
  version (0.147.0); documented as a known limitation, not silently
  assumed safe.
- Two provider-performance modules currently overlap in purpose
  (`src/provider_registry.py`, `evaluation/provider_performance.py`) —
  flagged as a next step in the readiness report, not a security or
  policy risk.

## Security considerations

Manual grep-based review performed (no live Codex-run adversarial review
executed in this pass): no `shell=True`, no hardcoded secrets in new
modules, `ai_run_log.py` scrubs secret-shaped keys defensively, forbidden
financial capabilities are rejected structurally in
`TaskEnvelope.validate()`, no new code path writes to `approvals/`,
`execution/human_requests/`, or `data/ledger.csv`. Full findings in
`journal/reviews/codex-provider-integration-readiness.md` section 14.

## Rollback

(`AI_OPERATING_MANUAL.md`, `HUMAN_GATES.md`, `CRITICAL_DECISIONS.md`,
