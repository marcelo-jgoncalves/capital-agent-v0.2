# System Change: Formalize interactive-session approval authentication convention

- Date/time: 2026-08-10T11:21:34-03:00
- Change ID: SYS-20260810-8E8A9C
- Change class: A
- Status: PROPOSED_AUTONOMOUSLY_ALLOWED

## Problem observed

The Phase 0 readiness audit flagged that approvals/pending/<id>.md's Human decision field has no cryptographic proof of human authorship. The human owner confirmed exclusive access to the operating machine and asked to formalize an interim convention now, to be strengthened later if the experiment proceeds.

## Evidence

Raised in `journal/reviews/phase0-readiness.md` item 5, then discussed
directly with the human owner in this session. Human owner's own words
(paraphrased from the conversation, this session): confirmed only they have
access to this machine, and asked to formalize the interactive-chat
authorization now, with the explicit intent to improve it later if the
experiment goes well. This is exactly the kind of explicit human decision
`context/knowledge/open-questions.md` said this open question needed before
being closed for the interactive case.

## Proposed change

Added approve-decision and reject-decision commands to src/capital_agent.py, which record the human's literal statement (--human-statement) plus a timestamp into the approval file, explicitly labeled 'interactive session, single-operator machine'. Documented the convention and its limits in CRITICAL_DECISIONS.md (new 'Approval authentication' section) and HUMAN_GATES.md Gate H7, explicit that it does not extend to unattended/scheduled sessions. Updated context/knowledge/open-questions.md to record this as a human-confirmed, scoped trade-off rather than a silent gap.

## Expected benefit

Standardizes an auditable quoted record of what the human said, instead of an unstructured manual file edit, without pretending it solves an authentication problem it cannot solve. Makes the scope limit (interactive-only, single operator) explicit in the same documents that govern critical decisions, so a future AI session cannot assume this convention extends to autonomous operation.

## New risks introduced

- Does not add any real authentication strength beyond the pre-existing
  manual-edit convention; it only standardizes the format. Explicitly
  documented as such in `CRITICAL_DECISIONS.md`, not oversold.
- Could be mistakenly assumed to extend to unattended/scheduled sessions by a
  future AI operator skimming too quickly. Mitigated: both
  `CRITICAL_DECISIONS.md` and `HUMAN_GATES.md` state the scope limit in the
  same section that introduces the convention, and
  `context/knowledge/open-questions.md` restates it as unresolved for the
  autonomous case specifically.

## Authority impact

None. This does not grant the system any new authority — it only changes how
an already-existing, always-manual approval field gets written, and by whom
it can be invoked (still requires a human's literal statement as an
argument). No hard limit changed.
