# System Change: Move decided approvals out of approvals/pending/ automatically

- Date/time: 2026-08-10T12:39:43-03:00
- Change ID: SYS-20260810-B3962E
- Change class: A
- Status: PROPOSED_AUTONOMOUSLY_ALLOWED

## Problem observed

context/CURRENT_STATE.md listed APR-20260810-7BFB0C as a pending critical-decision approval even though it had been APPROVED an hour earlier, because approve-decision/reject-decision wrote the decision into the file in place but never moved it out of approvals/pending/. Found while answering the human owner's question about what steps remain -- the status panel itself was misleading.

## Evidence

`context/CURRENT_STATE.md` (regenerated before this fix) listed both
`APR-20260810-3DA546` and `APR-20260810-7BFB0C` under "Pending
critical-decision approvals" even though both files already contained
`APPROVED` under `## Human decision`. Confirmed by reading both files
directly. Root cause: `build_current_state()`'s pending list is
`_list_md_ids(APPROVALS_PENDING_DIR)`, unconditional on content, and
`approve-decision`/`reject-decision` never relocated the file.

## Proposed change

_record_human_decision now moves the file from approvals/pending/ to approvals/archive/ after writing the decision, mirroring the execution-request lifecycle (pending -> exactly one terminal location). _approval_decision already checked both directories, so nothing that references an approval by ID breaks. Manually moved the two already-decided approvals (APR-20260810-3DA546, APR-20260810-7BFB0C) that predate this fix.

## Expected benefit

context/CURRENT_STATE.md's pending-approvals section now only ever lists approvals actually awaiting a decision, which is what a future AI session (or the human) reading it needs to trust.

## New risks introduced

None identified. `_approval_decision` already searched both
`APPROVALS_PENDING_DIR` and `APPROVALS_ARCHIVE_DIR`, so `request-execution`
and anything else that resolves an approval by ID is unaffected by where the
file physically lives.

## Authority impact

None. Purely a status-reporting accuracy fix; no policy value or approval
outcome changes, only where the decided file is stored.

## Rollback plan

`git revert` this commit; functionally, decided approvals would simply stay
in `approvals/pending/` again, which is cosmetically wrong but not unsafe.

## Validation plan

`python -m unittest discover -s tests`; regenerate `context/CURRENT_STATE.md`
and confirm the pending-approvals section is empty when no undecided
approval exists.

## Tests/checks performed

Updated `test_approve_decision_quotes_human_statement_verbatim` and
`test_reject_decision_quotes_human_statement_verbatim` to assert the file
leaves `approvals/pending/` and lands in `approvals/archive/`. Full suite:
48/48 passing (`python -m unittest discover -s tests`, run 2026-08-10).
Manually moved the two pre-existing decided approvals and confirmed

section.
