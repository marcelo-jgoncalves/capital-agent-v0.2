# System Change: Make context/knowledge/ consultation mandatory before new opportunity research

- Date/time: 2026-08-10T16:22:23-03:00
- Change ID: SYS-20260810-A54ECC
- Change class: A
- Status: PROPOSED_AUTONOMOUSLY_ALLOWED

## Problem observed

Three business-model candidates were rejected in a row for the same underlying reason (context/knowledge/recurring-errors.md) before that pattern was written down. The knowledge existed but nothing required consulting it, so it would have been just as easy to repeat the mistake a fourth time as to avoid it. Human owner asked explicitly whether there was a way to learn across decisions, and confirmed this gap should be closed before continuing further opportunity research.

## Evidence

Human owner's own words, this session: "Temos alguma maneira de aprender no
processo, qual quer que seja ele? Você acabou de tomar decisões
importantes e mudar a rota. Isso melhorou o resultado." followed by
explicit confirmation to close this specific gap ("sim. faça isso e depois
prossiga") before continuing to the next opportunity-research step
(`DEC-20260810-C5EA4F`'s primary-source verification step).

## Proposed change

Added a 'knowledge-check' CLI command that prints recurring-errors.md, rejected-opportunities.md and lessons.md in full. Added a new 'Before new opportunity research' section to AI_OPERATING_MANUAL.md requiring this command be run before starting a new opportunity-research pass, framed as required, not optional-if-convenient.

## Expected benefit

Removes the excuse to skip three manual file reads by making the check one command; documents the requirement in the same canonical manual that already governs the capital decision process, so a future AI session finds it as part of required reading, not as an easily-missed convention.

## New risks introduced

Still not code-enforced -- an AI operator could still skip running
`knowledge-check` since nothing blocks `propose`/`new-experiment` on having
run it first. This is a deliberate, documented limitation, not an
oversight: the same pattern already used throughout this project (e.g. the
`--reserve-instrument` self-declared flag) is that some things cannot be
verified by code and rely on the operating AI following documented process,
with auditability as the backstop rather than a technical lock. A stronger
version (e.g. requiring a `--knowledge-checked` flag on research-related
commands) was considered and deferred as unnecessary friction unless this
step actually gets skipped in practice.

## Authority impact

None. Process/documentation change plus a new read-only CLI command; no
financial authority or hard limit touched.

## Rollback plan

Remove the `knowledge-check` subcommand and the `AI_OPERATING_MANUAL.md`
section via `git revert`. No data depends on this existing.
