# Roadmap

This roadmap is independent of any particular AI provider or CLI.

## Phase 0 — Foundation (now)

- [x] Create mandate and hard policy.
- [x] Create initialized BRL 1,000 ledger.
- [x] Create human-gate policy.
- [x] Create decision journal format.
- [x] Create experiment registry.
- [x] Create local CLI.
- [x] Create unit tests.
- [x] Create vendor-neutral AI operating manual.
- [x] Create explicit self-improvement governance.
- [x] Create system-change journal.
- [ ] Initialize version control on the operating machine.
- [ ] Configure the chosen AI execution environment.
- [ ] Run Phase 0 readiness audit with the chosen AI.
- [ ] Run first opportunity research cycle.

Exit criterion:
The AI can inspect state, improve the system within allowed classes, create proposals
and produce auditable decisions without moving real money.

## Phase 1 — Data and shadow portfolio

- Connect reliable market/macro data.
- Add current low-risk BRL benchmark.
- Build quote cache with timestamps/source provenance.
- Add candidate scoring.
- Add paper portfolio.
- Add commercial-experiment scoring.
- Add periodic system-quality review.
- Schedule data update and allocation review using an environment-appropriate
  scheduler/orchestrator.

Exit criterion:
At least one complete decision cycle from discovery to shadow measurement and one
validated self-improvement cycle.

## Phase 2 — First bounded live experiment

Choose the highest-evidence opportunity found in Phase 1. Its form is deliberately
not predetermined: listed asset, crypto, paid product validation, domain/hosting,
resale, small software/API experiment or another legal bounded-loss opportunity.

The live amount must comply with active policy.

Exit criterion:
One real experiment has been funded, measured and reconciled.

## Phase 3 — Bounded automation

- Select official execution adapter(s).
- Implement dry-run and idempotency.
- Integrate an appropriate secret store.
- Add per-action and daily monetary limits.
- Add kill switch.
- Reconcile against external account/system.
- Require human approval for first adapter activation.

Exit criterion:
Small whitelisted actions can execute autonomously without unrestricted account
authority.

## Phase 4 — Capital allocation and continuous improvement

- Compare heterogeneous opportunities on expected return, downside, capital lock-up,
  evidence quality and feedback speed.
- Scale winners and shut down weak strategies.
- Maintain opportunity-cost benchmark.
- Produce periodic capital report.
- Use the system-improvement loop to refine workflows, models, tests and architecture.
- Periodically test portability by having a different capable AI reconstruct current
  state from repository artifacts only.

## Milestones

1. BRL 1,000 -> BRL 1,100
2. BRL 1,000 -> BRL 2,000
3. BRL 2,000 -> BRL 5,000
4. BRL 5,000 -> BRL 10,000

Milestones are measurement points, not deadlines.

## Cross-cutting systems

Required across all phases: Context Management System; Evaluation & Critic System; Critical Decision Approval System; System Evolution/self-improvement loop; and AI/model portability. Before meaningful live deployment, critic review and criticality classification must be tested, approval requests must persist, and live adapters must reject unapproved critical actions.
